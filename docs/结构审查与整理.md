## 后续优化优先级

1. **reuse：清理 `backend/api/schemas.py` 的重复配置与隐式导入。** 该文件含五个与 `settings.py` 重复的常量，能力和用例路径在本次迁移中已同步指向 `resources/`，仍有两份定义。多个模块通过 `from api.schemas import *` 引入模型及第三方符号。后续先改为显式导入，再移除重复常量和无用导入；不要直接删导入导致其他模块失去隐式依赖。
2. **shrink：按页面维护压力拆分大组件。** 商城 `frontend/src/shop/App.tsx` 约 1,185 行，后台 `frontend/src/admin/App.tsx` 约 1,037 行。下次修改订单或售后页面时，可将对应页面提取到同工程的独立组件；保留现有共享 API 和样式。此次没有为了目录整齐一次拆完全部页面。
3. **shrink：收窄 Agent 主类职责。** `backend/agent/customer_service_agent.py` 约 869 行，已有工具、RAG、工作流独立模块。下次调整某条业务分支时，优先复用已有模块，不另造全局插件框架或继承层级。
4. **delete：发布包按用途决定是否携带 Maven 缓存。** `ecommerce-backend/docker/m2-cache.tar.gz` 约 151 MB，当前 Dockerfile 实际用于依赖预热，保留。仅在确认联网构建稳定、无需离线教学包后移除缓存及相应 Dockerfile 分支；缓存目前也没有完全覆盖 Spring Security 构建依赖。
5. **reuse：后续统一默认环境文件位置。** `settings.py` 默认读取项目上级目录的 `course.env`，schemas 中残留定义却指向项目根目录。当前 README 使用显式 `AGENT_COURSE_ENV` 规避此差异；修改默认加载行为可能改变密钥来源和模型调用，需独立验证，未顺手调整。

当前没有增加依赖；本轮删除无用资源和备份，保留实际构建需要的缓存与独立工程。
