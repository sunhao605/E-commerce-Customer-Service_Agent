## 1. 产品判断与目标

**工具和知识提供事实依据，现有最终模型负责把本轮全部有效证据组织成一条顾客能理解的回复；系统负责校验、必要降级和业务执行边界。** 正常生成路径不再由模型解释一遍、系统再插入另一份能力说明。

典型任务：顾客问“轻量露营折叠椅现在多少钱，有货后能提醒我吗？”系统分别查价格库存和当前渠道的提醒能力，统一答清两个诉求。答复表达可以变化，但不能遗漏提醒、重复结论、编造登记动作或让顾客重新说明已经明确的需求。

本需求要解决的是最终答复的内容归属，覆盖独立咨询和已支持的混合咨询；不把它缩成“删掉某条到货提醒文案”，也不把它扩大为重建整个Agent。

### 1.1 成功标准

1. 正常模型回复是唯一的正文来源，没有能力占位符替换、事后追加目录说明或把完整模板与模型正文拼接。
2. 本轮已计划并取得的商品、知识及能力证据在最终生成前可用；每个已识别诉求得到回答、缺信息澄清或不能确认的说明。
3. 支持状态、具体订单资格、实际执行状态分别说明，互不替代；只读咨询不创建或提交申请。
4. 同一对象、同一时点的同一结论／下一步不重复呈现；不为简短删掉必要资格和未执行限制。
5. 生成失败、被跳过或校验发现问题时，使用一条完整可信的替代回复，保留所有已核实事实和必要缺口，不采用“错误生成＋补一句”的修补方式。
6. 不增加新的路由／评审模型调用，不以纯能力咨询专用捷径替代统一最终答复，不扩大工具、业务写入或服务承诺范围。

取消双重成文机制不等于保证模型永不重复；自由文字的事实一致性、完整性和同义复述必须通过真实任务评测，不能仅凭Prompt或格式宣称保证。

### 3.1 本期范围

- 当前走最终模型的普通只读咨询：商品事实／知识、政策及其已支持组合、服务范围及夹带能力询问。
- 本轮能力取证成功、未登记、超时、错误，以及商品／知识部分成功时的完整说明。
- 正常生成、模型失败、现有必要澄清／直接答复分支的同一最终正文选择规则。
- 保留已有待办、商品候选、政策待补、确认与审批隔离，以及Trace可追溯性。

统一职责不等于每条请求都强制调用模型。现有安全／低置信、本人资格核验、必要澄清、事实读取故障、受控运行上下文、明确申请流程及缓存等跳过生成分支，保留其业务理由和完整可信回复。本期不为了形式统一取消这些边界；独立能力咨询不新增专用跳过生成规则。

## 4. 目标请求流程

1. 加载本用户会话和受控上下文，完成既有意图及业务边界判断。
2. 使用现有RoutePlan执行需要的工具、知识和能力查询；分别记录成功事实、未知状态和本次失败。
3. 准备最终生成所需证据，同时在本地准备一条完整可信的替代回复。
4. 符合既有生成条件时，由现有最终模型直接生成整条自然中文回复。没有模型生成条件时，直接采用完整替代回复并记录原因。
5. 对生成结果执行本期明确的边界／内容检查：通过则呈现模型正文；失败则呈现完整替代正文。两种正文互斥，不再次插入能力说明。
6. 返回既有响应结构，由网关和页面呈现；按既有机制写回聊天及会话状态，不产生新的业务写入。

只有本轮需求变化、需要新对象或有效刷新理由时才允许新增查询；本次文案改造不应改变既有取证次数。商品库存与提醒能力是两项不同证据，不作为冗余调用合并。

## 5. 功能需求

### FR-01：正常回复由最终模型完整成文

删除正常路径对`[[capability:...]]`的生成要求和替换流程；模型可以直接说“暂时没有这项提醒功能”等符合证据的表达，不要求逐字使用目录说明。

应用不能因模型已经答对而仍追加能力段，也不能因主意图不是服务范围咨询就忽略已取得的能力证据。若旧占位符意外出现在结果中，视为旧格式或无效输出，记录原因并整体降级，不把标记展示给顾客，也不默默删除后接受可能漏答的回复。

### FR-02：给模型的是事实依据，失败候选单独管理

复用现有`tool_observations`、`citations`、`context_builder`、公开Workflow结果和能力查询结果，不要求新建统一证据平台。能力证据至少保留当前ID、渠道、支持状态、范围、解释、可行下一步、版本和本次失败；解释可以是文字事实，不能被当作必须另发的完整答复。

`answer_reference`不再是生成输入必需字段；`answer_text`只在确定性直接答复／降级确有用途时保留，不能与正常回复再叠加。完整降级稿优先留在应用侧。工程若需要从既有`deterministic_answer`中保留其他分支尚未进入模型payload的事实，必须先核对并迁移其必要信息，不能盲删`fallback_answer`导致订单／政策信息丢失。正常payload中同一能力避免同时作为完整草稿、成品答复项和占位符说明重复提供。

支持状态只取本轮目录查询结果。Prompt描述“依据已核实状态、不得误称动作已完成”，不独立维护“永远不支持某能力”的事实。测试可合成支持状态变化，不修改日常目录来迁就测试；支持某项功能仍不等于本次已经登记或执行。

### FR-03：回答范围与表达

先回答顾客原问题，保留影响判断或下一步的必要限制。各已识别诉求只需充分说明一次；同一句意思换词再说而没有新信息，也计重复。金额、库存、政策条件、期限和服务支持均须来自本轮有效证据；缺少时明确不能确认，不凭常识补齐。

不把同关键词当重复：“当前支持退款”“这笔订单尚未核验资格”“没有提交申请”是不同结论，必要时都要说明。用户没问提醒、明确不要提醒时，不机械加入提醒状态。下一步须来自可行能力或已有流程，不承诺占位人工入口有人接手。

示意输出，不作为固定匹配文案：

| 顾客问题与证据 | 合格答复示意 |
|---|---|
| 支持到货提醒吗；接口unsupported | 当前暂不支持到货提醒，你可以稍后主动查库存。 |
| 折叠椅多少钱，有货后提醒吗；价格199、库存0、提醒unsupported | 这款折叠椅目前199元，暂时无库存。当前不支持到货提醒，你可以稍后再查库存。 |
| 支持退款吗；支持符合条件的未发货整单退款 | 支持符合条件的未发货整单退款。具体订单还要核验资格，目前没有提交申请；需要时可以提供订单号。 |
| 有货吗，能提醒吗；商品读取超时、提醒unsupported | 这次暂时没查到库存，不能确认是否有货。当前不支持到货提醒，可以稍后再查。 |
| 支持某服务吗；能力接口超时 | 这次没查到这项服务的支持状态，暂时不能确认，请稍后再问。 |

上表199元只代表基线示意／测试fixture，真实验收按当次API事实判断。顾客未要求办理时，提供订单号只能是后续资格核验的选项，不生成申请。

### FR-04：内容检查与可验证边界

**取消占位符检查不能等于取消所有保护。** 本期至少保留空输出、旧标记泄漏、已识别的未执行动作承诺、安全及业务执行边界检查，并覆盖“模型只回答商品价格、遗漏本轮已查询能力”的回归：该已发现漏答模式必须得到完整降级，不能沿用只答价格的结果。

首版可做针对已查询能力状态及必要回答项的窄检查，但不能仅用目录原文是否出现来判定，也不能把合法同义表达判为不完整。工程必须在实施结果写清：哪些由代码自动识别，哪些只能通过语义评测确认；给出正常表达及漏答／错误表达的测试。无法证明的任意自然语言覆盖率不写成保证，不新增通用语义审核模型。

能力范围、商品事实、资格和执行状态不同。已知状态冲突／关键漏答被识别后整条降级；自然语言同义重复和任意事实一致性仍纳入助手／人工语义审阅。若技术方案无法同时处理已知漏答与合法同义表达，必须报告具体缺口及取舍，不能通过放松标准、仅增强Prompt或伪造字段自证完成。

### FR-05：完整降级，不拼接补句

模型无配置、错误、超时、空输出、旧格式或可识别的关键缺项／状态冲突，均使用同一批证据生成的完整替代回复。它应保留已成功查询的事实、能力限制及本次缺口；失败状态不变成“不支持”，部分失败不掩盖已核实部分。

沿用必要的未执行动作删句防护。删句后如丢失必答项、留下不完整回复，必须整条降级，不能继续追加目录句。降级稿可以用确定性工具摘要和能力解释，但每个内容块只呈现一次；现有生成前草稿组织可复用，不另建方案二的通用模板引擎。记录实际所选回复来源和具体降级原因。

本期不增加自动重试次数或额外模型调用。模型失败不能触发工具重查或业务动作重试。

### FR-06：来源与运行观察

移除正文占位符不移除来源。保留既有路由需求、RoutePlan、能力ID／状态／版本／failure、工具及知识结果、模型生成／跳过、实际降级原因。继续可以核对查询发生在生成前、计划和执行一致，以及正文来自模型还是确定性路径。

复用已有Trace及`session_state.model.final_answer`字段；仅确实无法区分正常、跳过或整条降级时补最小字段。不要新增保存凭据、完整隐藏推理或不必要用户原文的日志。原回复、公开Trace及源码／配置指纹用于复测，模型替换前未留存的历史原文仍标未知。

### FR-07：会话、权限与执行结果

只读插问不清掉退款待办、商品候选或政策待补，不重发旧确认卡，也不创建新Workflow。本人订单资格仍通过原工具及身份约束，模型不得用服务支持状态替代具体资格。

已有申请／审核／资金操作由原Java执行层和确认流程决定，模型不改变pendingAction、凭证或审批。未查询资格不得说该单可退；未完成登记不得说已登记；人工占位入口不得说真人已接手。页面中的核对或确认信息有明确价值时不当作冗余删掉。
