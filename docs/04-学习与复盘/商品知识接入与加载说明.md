# 商品知识接入与加载说明

日期：2026-10-12。用户明确授权接入商品知识检索链路，并重启服务加载前一轮扩充的材料。本轮接入及加载完成，当前日常商城可使用。

## 1. 商品事实与知识的分工

- 通用搭建、保养、收纳、冷凝、温标等问题走商品知识。已说明商品类别时不强制选择 SKU；类别缺失时澄清，最近已查商品可用于知识追问。
- 价格、库存、规格、活动或推荐仍走商品工具；同时问使用知识时，在确定对象、读取成功后再补指南。不用知识填充未知实时字段，也不在候选澄清或读取失败时冒充已知商品。
- 商品咨询保持原来的 product_query 标签，保留候选绑定、故障反馈与退款待办边界。本轮没有增加售后、发券、维修或赔偿动作。

## 2. 检索与引用

商品指南按 Markdown 小节组织，再用 220 字符／30 重叠切块。召回小块后回取同一小节，保留条件和例外。按商品主题先过滤，保养问法归一到清洁收纳；明确问收纳、温标等时优先对应小节，避免型号名称把概述排在操作前。

对顾客只展示一个最相关小节，去掉 Markdown 标题和链接语法；完整原文、来源、小节 ID、命中块 ID 与版本保留在 Citation。现有商城是纯文本回复，Python 引用契约与 Trace 可查，未增加商城引用卡。知识与实时商品信息拼接后仍先形成确定性话术。2026-10-15 起最终模型可以改写这段话术；若改写承诺到货提醒或帮顾客留意补货，则丢弃改写、用回确定性话术。价格或库存字段缺失、接口超时仍不改写。

混合索引从 56 增到 85 块，五个文件为退款、发票、活动、会员和商品指南。签收退货继续直接读取指定文件，重启后使用扩充正文，不纳入混合索引。启动时预加载，`/health` 可看到 loaded、version、chunk_count、files 和 embedding。

本轮同时修复接入长文必需的三个检索问题：先按域过滤再取 TopK；同政策／小节的多块向量分取最大值；缓存 key 包含 TopK。其他政策仍保持原来的政策级引用，本轮没有统一改成片段级引用。
