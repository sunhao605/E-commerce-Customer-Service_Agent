## 开始前

打开[本地商城](http://127.0.0.1:5174/)，刷新并以张三（`zhangsan`）登录，在首页点击“客服”。每句话单独发送，等系统回复后再发下一句。

每条链路开始前刷新页面并重新打开客服，确保从新会话开始；仅关闭再打开客服不会清空会话。本次不新建订单、不支付；退款链路停在确认卡，不点击“确认提交申请”。

## 链路一：多款选择与连续追问

### 第1步：查询类别

```text
折叠椅多少钱？
```

预期：列出多款候选，让你选择；不直接替你选第一款报价格。

### 第2步：选择第二款

```text
第二款
```

预期：回答列表中第二款的名称及价格、库存。当前核验的列表第二款为“轻量露营折叠椅”，标价199元，库存0件；不能答成普通“露营折叠椅”的599元。

### 第3步：追问刚才那款

```text
刚才那款还有库存吗？
```

预期：仍查询刚选定的商品，不再让你选款，不换成第一款；当前应说明库存0／暂无库存。价格、库存是加载时只读快照，之后的管理端修改以实时接口值为准。

这条链路的通过标准：先选对象；“第二款”绑定正确；后续指代仍是同一款。

## 链路二：退款草稿不被商品咨询打断

先刷新页面，重新在首页打开客服。使用张三账号；下面已填入本人现成演示订单，不用创建新订单。订单在加载前只读核验为已支付、未发货、可申请整单退款199元。

### 第1步：准备原退款确认卡

```text
SO20261010124526068-3c464bb6 我要申请退款，原因：买错了
```

预期：显示这笔订单的退款确认卡，原因是“买错了”，状态是尚未提交。停在这里，不点击“确认提交申请”。

### 第2步：插入商品咨询

```text
折叠椅多少钱？
```

预期：列出商品候选；不重复发退款确认卡，不把这句当成退款原因或换单操作。上方原退款卡的按钮仍可用。

### 第3步：使用数字序号选择

```text
第2款
```

预期：回答刚列出的第二款，不能询问退款订单或退款原因；原退款卡仍可用。

### 第4步：回到退款

```text
继续办理退款
```

预期：继续原订单的退款流程，保留原因“买错了”，展示／续接确认卡；不再次追问是哪笔订单，不换单、不提交退款。

这条链路的通过标准：商品查询没有改旧退款；“第2款”属于商品选择；回到退款能继续原订单。

## 怎样反馈

两条都符合预期，回复“商品定位手测两条都没问题”即可。出现问题时，记录链路和步骤、实际回复，以及按钮是否失效；不必扩大测试。
