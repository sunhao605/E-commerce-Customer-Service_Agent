## 已修正与剩余 BadCase 的归因

- **BC-007 的错主题问题：本次 B01 未复现。** 当前新增退款咨询标签接入退款政策，发票另用 `invoice_query`，不再进入固定发票分支。仅确认这条 Python 输入的修正，不关闭所有咨询或缓存风险。
- **BC-008 的咨询变办理问题：本次 B02 未复现。** 新退货咨询标签对应低风险只读计划，无强制订单或办理待办；内容不合格另记 BC-009。
- **BC-009 的范围与原因要求不清：通用退货SOP被直接用于七天无理由咨询。** [退货政策文件](../backend/resources/knowledge/received_return_policy.md#L8) 原文仍要求“用户提供明确退货原因”；[policy_query_result](../backend/retrieval/knowledge.py#L59) 直接选择这份已加载的政策对象，最终回答模型复述该条件。与 [ShopService 提交逻辑](../ecommerce-backend/src/main/java/com/teachdemo/ecommerce/order/ShopService.java#L394) 对照，七天无理由申请固定记录该类型，不接收另填原因；[资格核验](../ecommerce-backend/src/main/java/com/teachdemo/ecommerce/order/ShopService.java#L455) 检查支付、签收、窗口和购买时可退快照。针对无理由咨询的额外原因要求来自引用来源，不能只归为模型编造；没有证据说“商品须支持退货”这个条件错误。模型同时没有补全来源缺少的办理流程。

## 剩余问题的最小修正方案

先只同步 `received_return_policy.md` 的适用范围：明确七天无理由仅适用于购买时支持该服务的商品，无需另编原因；其他售后不能据此省略问题或原因说明，也不能一律拒绝。写入已确认的支付、签收七天窗口、整单购买时可退条件，以及确认提交→待审核→同意后寄回→验收通过才退款的流程。不要再增加意图标签；本轮两个标签已完成目标分流。

退款材料也可在同一政策同步范围内补全整单、本人确认和管理员独立审核，但这是覆盖完善建议，不把 B01 写成已观察到新的错答。修改后需重启 Agent：政策对象在模块导入时加载，仅修改文件不会刷新运行中的对象。先重跑 B02 验证额外原因要求消失、流程准确、只读状态仍保持；若正确来源仍被模型改写错误，再定位最终回答约束。本轮仅记录方案，未实施。
