## 首轮 DISPATCH-PAGE-001 失败根因（已修复）

1. **serve.py 路径 bug**：`REPLIES_PATH` 用 `parents[2]` 定位到 `analysis/` 而非 `analysis/02-意图与政策咨询/`，导致回放源文件找不到，所有回放轮降级为真实模型调用。
2. **回放匹配失败**：Java 网关在 `buildAgentMessage` 中把页面上下文拼接到用户消息之后，精确匹配失效。改为前缀匹配。
3. **P02 会话 seed 落空**：浏览器实际会话 id 由前端生成（`cs-uuid`），与 runner 预置的 `dispatch-page-p02` 不同，种子从未落到实际会话。修复：T2 发送前从浏览器响应取实际 session id，再调 `/api/check/seed` 和 `/check/seed/{session}` 补种。
4. **P02-T1 检查误报**：回放轮 serve 返回的 `session_state` 是 DISPATCH-LIVE-001 当时的快照（open_task=null），但 Java 网关不会把回放响应的 null open_task 写进内存。T1 时种子尚未落到实际会话，runner 读到 null 属正常时序，非产品缺陷。T1 只校验「无确认卡 + 答复包含知识关键词 + 页面无卡」。
