# 取消判断定向修改与复测：CANCEL-COMPARE-002 / 002B

日期：2026-10-11。只修改实验中的问题描述、三项组合决策及测试输出解析，不接入商城。新20条与旧30条逐条原话均不同，每条两次；助手同作者合成，不是外部盲测或线上成功率。旧30条用于调试/回归；英语版在查看旧样本结果后冻结，未根据新20条输出修改问题、标准或阈值。

## 为什么Jev上次不应直接取消的输出比DeepSeek多

001中Jev的12次全部来自6条需澄清/复合样本两轮错误；明确取消24/24、明确不取消20/20正确。DeepSeek的8次包含7次澄清类和1次明确继续被错判。原cancel描述允许明确结束当前售后，clarify又包含取消加新任务，两类语义有交集：例如“先取消申请，再查物流”既有取消意愿又不是单一动作。Jev更常选择意愿类，DeepSeek更常遵循复合处理类；这是输出事实，不能据此证明训练架构或中文能力是根因。

原实验把“有取消意愿”和“能直接进入单草稿取消分支”合并成一个分类。官方建议一次只问一个明确问题，并列出字面理解、复杂指令、选项顺序等限制。两版定向实验支持拆分和澄清描述有帮助；变更同时包含拆分、说明细化及语言变化，未做独立消融，不能分别归因。来源：[原结果](../取消语义对比/结果.md)、[原子问题](https://docs.typesafe.ai/introduction)、[已知限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。

## 改了什么

1. 模型分别判断decision（stop / continue / uncertain）、target（current / other / ambiguous）、extra_task（yes / no / uncertain）。Jev一次API请求并行回答三个Choice；DeepSeek单次返回三个字段。
2. 代码组合：continue→keep；uncertain→clarify；stop且current且没有新任务→cancel；其余→clarify。缺失/非法输出→invalid，不触发取消。后台是否有本人有效未提交草稿仍由独立门控负责。
3. 英语细化版强调取消订单与取消退款申请不同、含糊省略不能直接推定取消、未核实条件不是最终决定。输入仍是中文。没有增加业务关键词匹配或改当前商城Prompt。
4. 兼容DeepSeek字段字符串和choice/type中已经给出的有限枚举；只做结构解析，不推测自由文本。clarify标签沿用001，含“澄清对象”和“复合请求另行编排”，不意味着每条复合请求都要求用户重复确认。

## 运行与解析修复边界

初次DeepSeek拆分输出在测试器触发TypeError，中文27次、英语32次；这是测试器错误，不能当模型语义失败。原始失败记录完整保留到各split_deepseek-parser-before.jsonl，但当时异常前回复及usage未保存，不能补编。修复后两个DeepSeek拆分方案各重跑40次，保存完整回复；其字符串或choice/type枚举用确定性解析重建结果，解析前文件保留在split_deepseek-before-normalization.jsonl，未因此再调用模型或改标签。详见两份parser-repair.json。

本轮共440次实际模型调用：A220＋B140＋解析修复重跑80；另40次本地规则仿真。最终评测表只使用完成后所列运行，不挑成功轮。表内费用是可核算各最终运行的usage估算，不是整个实验账单；初次解析异常的59个回复缺usage，全部实验费用无法精确核算。Jev价格10-11官网复核一致；DeepSeek抓取超时，沿用10-10峰谷价。两版测试及修复重跑不在同一时间窗口，不能按表中速度断言某模型永久更快。

预设零误取消与无漏识别成功标准未通过。定向改动减少危险输出，但没有解决所有边界；不部署、不执行真实取消。下一步应针对保留错误设计更简单的独立判定或澄清路径，用新的未调参样本验证，并修正DeepSeek输出契约后再做性能选型。
