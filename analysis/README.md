## 怎样阅读一个专项

1. 先读结果说明或 README，确认时间、版本、入口、数据和判定范围。
2. 再查 result/checks/verification 等结构化结果，沿其记录核对完整对话、Trace、截图与日志。
3. run/check 脚本说明当时如何验证；冻结样本、manifest 和 before/after 文件用于复核。不要只凭 HTTP 成功或一张截图认定业务完成。

## 保留规则

- 一次验收的材料不按文件类型拆散；多次运行、修复前和失败轮次保留各自子目录。
- .runtime 是隔离编译与临时运行材料，.before 等是当时的源码快照；阅读时跳过，复核时按专项说明使用。本次未清理这些内容。
- 原始 JSON、JSONL、日志、diff、冻结哈希和截图保留原样。因此它们可能记载移动前的路径，历史哈希也不代表迁移后的运行脚本。
- 所有执行命令以项目根目录为工作目录。部分脚本会调用在线模型、启动服务或写入演示数据，执行前按该专项原有说明确认范围；本次目录检查只做静态验证。
