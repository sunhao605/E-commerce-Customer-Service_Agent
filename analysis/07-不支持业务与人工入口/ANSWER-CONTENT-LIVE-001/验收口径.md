# 真实小样本验收口径

本轮按用户要求跳过代码与PRD一致性复核，仅做真实模型验收。冻结15条请求：12条自然问题与3条本地故障注入；全部来自构造问题和演示材料。模型看不到样本编号、expected或评分标准。冻结前已确定各题期望，见 frozen.json。

逐题查看原问题、实际上下文、路由、选中规则、生成候选、judge与最终正文。以下五项分开记 pass / fail / uncertain，并用具体原句说明；不以judge通过替代体验合格：

1. 需求回应：明确问题均回应；多轮“那多久到账”要结合前文。不能只靠主题字段认定用户没有其他问题。
2. 事实与动作：仅按演示规则和fixture回答，不虚构个人资格、申请、登记、盯库存或人工接手。无知识、查询失败与unsupported区分。
3. 条件完整：保留影响结论的限制、例外和未知；通用优惠不证明具体SKU或本人券已经适用。
4. 相关性与重复：同规则表达一次；不附带未问的其他政策整段；必要条件不因用户没逐字问就删除。不设字数门槛。
5. 自然表达：按问题顺序给直接结论和必要说明；避免让顾客读内部ID、教学指导或机械关键词堆砌。

技术过程另记：真实路由是否used_model、主题是否有效、输出是否截断、最终来源、修复/复查次数、工具/能力/入口查询次数、待办保留、HTTP实际次数、usage与耗时。首轮失败保留，不自动重跑或修改业务源码后混算。

注入组单列：F01注入错误首稿，由真实judge核对并按原门槛修复或安全降级；F02注入judge超时，F03注入生成故障。注入不计自然超时率或自然模型错误率。真实路由输出仍来自当次模型，不手工补主题。

本轮不覆盖在线Embedding/真实商城/Java/MySQL/浏览器及历史落库；不据此宣称全链路生产验收通过。
