## 接口

`GET /api/customer-service/capabilities/{capabilityId}`

登录用户或 `X-Agent-Service-Token` 对应的 `ROLE_AGENT_SERVICE` 可以读。标识只允许 `^[a-z][a-z0-9_]{0,63}$`，不接受路径、类名或工具名。非法标识返回 400。未登记的合法标识返回 200，`supportStatus` 为 `unknown`。

字段沿现有 Java 驼峰风格：

```json
{
  "capabilityId": "stock_notification",
  "channel": "customer_service_agent",
  "supportStatus": "unsupported",
  "scope": "到货与补货提醒登记",
  "explanation": "当前客服助手不支持到货或补货提醒。",
  "alternatives": ["稍后主动查询商品库存"],
  "version": "service-capabilities-v1"
}
```

目录文件：`ecommerce-backend/src/main/resources/service-capabilities.json`。Java 启动时读取这一份，不另写一份状态表。

| capabilityId | supportStatus | 依据 |
|---|---|---|
| inventory_query | supported | 现有商品查询能读价格和库存。支持不等于某一件有货。 |
| stock_notification | unsupported | 没有到货或补货提醒登记接口。 |
| exchange_handling | unsupported | 换货仍进占位人工卡，没有换货申请。说明里写明不会接入真人。 |
| human_takeover | unsupported | 人工页是开发中占位。确认前往不是真人已接手。 |
| refund_consultation | supported | 未发货整单退款仍由原资格流程办理。这句话不等于已经提交。 |
| return_consultation | supported | 签收七天无理由退货同样只说明范围。 |

`supported`、`unsupported`、`unknown` 只描述渠道能力。订单资格和是否已经执行仍走原来的业务接口。

## 答复

Python 只查询本轮识别出的能力。识别仍是明确说法：到货提醒用现有 `wants_stock_reminder`；能不能、支不支持、支持吗用来识别库存、换货、人工、退款和退货。只问价格，或说不要提醒，不查询。

纯能力问题直接呈现查询结果，不追问商品名，也不查商品。价格加提醒仍查商品。商品读取失败时保留失败说明，再附上提醒不支持。查询超时或错误写成“暂时不能确认”，不写成不支持。

「支持退款吗」「支持退货吗」改走政策咨询，不进入退款或退货申请，也不清掉已有待办。「我要退款」「我要换货」「转人工」仍走原来的办理或占位卡。

商城网关对能力咨询直接返回 Python 的答复，动作名 `CAPABILITY_QUERY`，不重发待确认卡，也不清草稿。换货和转人工的办理句仍然出占位卡。
