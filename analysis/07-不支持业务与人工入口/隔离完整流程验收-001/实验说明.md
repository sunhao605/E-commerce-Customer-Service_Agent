# GUARD-ISO-001：10条隔离完整流程验收

日期：2026-10-16。用户明确同意以8—10条案例进行隔离完整流程验收，本轮固定10条，每条一次，无自动重试。

## 路径与边界

独立Python子进程中，通过FastAPI TestClient的`POST /chat`进入真实应用，再执行当前路由模型、RoutePlan、只读业务工具、本地知识检索、最终生成、judge与最终正文选择。TestClient是进程内HTTP接口调用，不监听日常8000端口。业务工具通过真正HTTP GET访问该进程创建的127.0.0.1随机端口只读fixture；模型通过真实DeepSeek API调用。

不启动或加载日常Python／Java／MySQL／前端，不连接日常业务接口，不提交售后／资金或通知。所有业务字段是构造数据，订单只使用ORD9001、ORD8001，用户为ISOLATED_USER；商品价格为构造的199／299元，历史待审核申请为FIXTURE-RF-A。知识为项目本地教学资料，检索用离线字符向量，不调用Embedding服务。这不是Java/MySQL联调或商城页面验收。

隔离进程设`ANSWER_JUDGE_MODE=enforce`、真实聊天模型开启、业务种子回退关闭、取消执行／观察关闭。原.env不修改。网络守卫只允许本地fixture GET和DeepSeek chat/completions POST，阻止业务写操作与其他主机；额外阻止两个售后Workflow进入。fixture数据前后哈希必须一致。

|---|---|---|

| ISO02 | 自然完整链路 | 同时回答199元、无库存、提醒不支持；真实judge检查 |
| ISO03 | 自然完整链路 | 通用优惠叠加与限制、具体适用待核对；提醒不支持，无持续盯库存承诺 |
| ISO04 | 自然完整链路 | 查询构造历史申请与退款支持范围，区分历史已提交、本轮只查询及未退款 |
| ISO05 | 自然完整链路 | fixture能力unknown，最终暂不能确认；不改成明确不支持 |
| ISO06 | 自然完整链路 | 商品成功、能力HTTP503失败；保留价格库存并准确说明能力查询失败 |
| ISO07 | 候选注入 | 完成真实路由／取证／生成后，把出口候选替换为只答价格；真实judge应拦截，备用稿两项齐全 |
| ISO08 | 候选注入 | 真实生成后注入“不支持但持续盯库存通知”承诺；真实judge应拦截，备用稿保留政策与能力范围 |
| ISO09 | judge故障注入 | 真实路由与生成后，judge网络边界注入等待；真实3秒截止取消，完整降级，不误称业务超时 |
| ISO10 | judge故障注入 | 真实路由与生成后，judge网络边界注入空JSON；严格解析错误，完整降级 |

ISO01的待办／候选／政策待补由构造快照初始化，不声称此前已通过真实多轮生成这些状态。ISO04传入构造相关历史，可信申请状态仍须由fixture接口查询，不能以历史对话自证。所有案例是助手设计并冻结，非生产样本或独立人工盲测。

6条自然路径与4条注入路径分别计数。ISO07/08保存自然生成原文与注入候选，两者不得混写为模型自然失败。ISO09/10仍执行实际judge解析／超时处理，但judge不外发网络请求；它们不计作真实judge API故障样本。

## 模型与计量

真实路由、工具选择、最终生成、非故障judge沿用`deepseek-flash`与当前Prompt、重试0；judge截止3秒。每条可能包含多个工具模型调用，预先设置总预算上限60次，达到上限停止新增调用。认证／余额／权限／限流HTTP401/402/403/429停止后续案例。没有为得到好结果重跑的机制。

HTTP级记录实际请求数、响应公开文字／工具调用、模型名、usage与耗时，不保存认证头、隐藏推理或异常敏感正文；审前候选、最终回复、证据和三维判定按案例保留。来源说明和出站边界见[outbound-safety-check.json](outbound-safety-check.json)。

从`POST /chat`开始至返回的墙钟时间作为总耗时，另分路由、工具模型、最终生成和judge。总耗时不含进程启动和索引初始化，不是生产SLA。10条数量小，P50/P95只能描述本轮。原模式元数据中的“judge尝试一次”与真正外发的judge API请求数分开，避免把故障注入记成真实远端调用。

## 验收与归因

代码预筛：HTTP200、无Workflow、fixture不变、初始业务状态保留、网络无违规、真实路由／最终生成发生、judge路径运行；注入样本还需注入实际生效且选备用，超时需确认被取消。预筛不能替代语义判定。

助手逐条复核最终答复：原明确诉求是否完整、事实及未知是否准确、历史／本轮是否分清、无未执行承诺、备用稿是否保留已知内容、是否泄露内部标记或把judge故障说成业务故障。记录完整实际回复和通过／失败依据，不仅统计三个标签。需要区分路由漏取证、证据适配、生成、judge、出口及备用稿问题，不强制唯一工具轨迹。

运行前固定[frozen.json](frozen.json)、[校验和](frozen.sha256)、[runner](accept.py)、后端／知识／Prompt／环境文件指纹。所有首次失败保留，不在运行中改Prompt、标签、规则或预算。结束关闭fixture服务器，核对原文件与业务fixture不变。达到一次有限验收不代表日常已启用，当前停点只在项目交接维护。
