# 工具故障反馈实现验收

日期：2026-10-12。范围只覆盖商品搜索和单品详情。未改订单、物流、售后工具，未新增意图、模型、依赖、自动重试或熔断。Java 和前端商品代码未改。未调用在线模型，未打日常商城，未写业务库。

规划在 [docs/缺口六工具故障反馈/工具故障反馈产品需求规划.md](../../docs/缺口六工具故障反馈/工具故障反馈产品需求规划.md)。正文第 1–6 节是写规划时的现状；当前停点以 [项目交接](../../docs/项目交接.md) 为准。`analysis/工具故障反馈设计核验/` 不计入这次验收。

## 代码改动

- `backend/agent/ecommerce_client.py`：搜索成功返回列表（空列表是零匹配）；超时记 `timeout`，其余读取失败记 `unavailable`。详情只有 HTTP 404 且业务码 `NOT_FOUND` 才是 `not_found`。`ecommerce_get` 未改。课程镜像仍只在 `AGENT_COURSE_OFFLINE_FACTS=1` 时使用，确认不存在的商品不回落到镜像。
- `backend/agent/tools/tool_runtime.py`：失败、零匹配、缺字段分开。价格须为非布尔数字且 ≥ 0，库存须为非布尔整数且 ≥ 0。0 是有效值。身份不成立或整批行不可用按读取失败，不说成没找到。
- `backend/agent/customer_service_agent.py`：超时和业务接口不可用同步 `degraded` 与 `degradation_reason`。失败和部分事实跳过最终回答模型，避免把超时改写成缺货。无匹配不是降级。失败不改退款草稿，已知商品编号留给重试。

`tools/langchain_runtime.py`、Hook、Prompt 未改。模型工具路径的最终回复取工具摘要，不取模型自己编的句子。

失败话术：`这次商品信息查询没有成功，暂时无法核实。请稍后重试。`  
无匹配话术：`没有找到与“{关键词}”匹配的商品。可以补充更完整的商品名称或款式再试。`

## 页面链路

只跑一条“查询失败 → 恢复”。隔离端口：页面 18103，Python 18101，Java 18102（内存 H2），故障代理 18114。`ECOMMERCE_BASE_URL` 指向代理，`AGENT_COURSE_OFFLINE_FACTS=0`。代理只对下一次 `GET /api/products*` 返回 HTTP 500。每次操作后截图在 `对话截图/01.png`–`04.png`。9 项检查全部通过，见 `page-checks.json`。

| 步骤 | 输入 | 页面回复 |
|---|---|---|
| 1 | `ORD9801 我要申请退款，原因：买错了` | 请核对申请，确认提交后等待后台审核。确认卡停在提交前 |
| 2 | `轻量露营折叠椅多少钱？` | 轻量露营折叠椅 商品标价 199 元，当前无库存。 |
| 3 | 注入一次商品读取 500 后，`刚才那款还有货吗？` | 这次商品信息查询没有成功，暂时无法核实。请稍后重试。 |
| 4 | `刚才那款多少钱？` | 轻量露营折叠椅 商品标价 199 元，当前无库存。 |

失败回复没有出现“缺货”“不存在”或标价 199。确认按钮仍可点，退款草稿未变，8 张 H2 业务表哈希未变，没有提交退款。这颗种子商品的库存本来就是 0，所以成功回复里的“当前无库存”是这次读到的事实。
