后台先同意退货，再确认验收和退款。第一次同意时，余额不变。

## A 客户与后台怎样配合 {span=2}
```sequence num
客户 -> 系统: 确认提交整单退货申请
系统 -> 审核员: 登记待审核，金额取实际支付流水
审核员 -> 客户: 同意退货，提供地址和联系人
客户 -> 审核员: 寄回商品，填写快递和单号
审核员 -> 系统: 确认已实际收到且验收通过
系统 -> 客户: 退回模拟余额，订单显示已退款
```

## B 哪些订单可以申请
| 条件 | 首版处理 |
|---|---|
| 本人已支付且已签收 | 核验归属、订单和支付流水 |
| 签收七天内 | 次日起算，按有效提交时间判断 |
| 整单商品支持无理由退货 | 使用购买时的可退记录 |
| 金额和事实缺失 | 提示人工核验，不生成申请 |
| 运输中 | 联系人工处理拦截 |

## C 审核员有两次不同操作
| 操作 | 填写或确认 | 余额 |
|---|---|---|
| 同意退货 | 退回地址、联系人、电话 | 不变 |
| 确认验收并退款 | 已收到商品且验收通过 | 恢复整单实付金额 |
| 驳回申请 | 说明具体原因 | 不变 |
| 验收未通过 | 说明异常，交人工核验 | 不变 |

## D 页面在哪里操作
| 角色 | 页面 | 操作 |
|---|---|---|
| 客户 | 订单详情的客服 | 提出七天无理由，核对并提交 |
| 客户 | 订单详情、售后记录 | 看进度、退回地址，填写物流 |
| 审核员 | 后台售后审批 | 同意退货或驳回 |
| 审核员 | 后台同一申请 | 收货验收后确认退款 |

## E 正常与异常怎么走 {span=2}
```flow LR
待审核 -> 待买家寄回: 同意并提供地址
待审核 -> 已驳回: 说明原因
待买家寄回 -> 待商家收货验收: 客户填写物流
待商家收货验收 -> 已退款: 确认收到且验收通过
待商家收货验收 -> 验收未通过: 记录原因
验收未通过 -> 已退款: 人工核实后确认验收通过
```

## F 退款完成时怎样变化
| 对象 | 结果 |
|---|---|
| 售后申请 | 已退款，处理记录可查 |
| 订单与支付状态 | 已退款 |
| 履约状态 | 已退回，保留原签收和发货记录 |
| 模拟余额 | 只增加一次整单实付金额 |
| 未发货退款 | 沿用原流程，履约显示已取消 |

## G 这次的范围
首版只做整单退货及模拟余额退款。

- 客户不能通过聊天批准申请。
- 退回单号不能证明商家已收货。
- 不做部分退货、物流拦截和运费结算。
- 不自动把退回商品加回可售库存。

## H 如何确认做对了
- 同意退货、填写物流时，余额始终不变。
- 未确认收货验收时，服务端拒绝退款。
- 重复或并发确认只产生一次入账。
- 第八天、未来签收和事实缺失不能放行。
- 及时提交的申请可继续等待后台审核。
- 验收异常可见，人工核实后可继续处理。

规则依据：[市场监管总局七日无理由退货办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_26ca8fe29e184edd899fa0a7a060d935.html)。详情见项目内的产品设计计划。
